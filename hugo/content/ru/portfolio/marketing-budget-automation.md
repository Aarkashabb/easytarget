Для рекламного агентства [VashTargetolog](https://www.instagram.com/vash.targetolog/) мы сделали отчёт, который ежедневно сводит в одну таблицу расходы на каждое объявление в Facebook и Instagram и продажи по товарам в магазинах-клиентах агентства. Раньше таргетолог считал расходы вручную, а магазины вписывали проданные единицы по дням сами. Теперь всё попадает в таблицу автоматически, а агентство решает, какие объявления масштабировать, а какие отключить, по свежим данным.

## Коротко о проекте

- Клиент: рекламное агентство VashTargetolog. Его клиенты: интернет-магазины разных ниш, а не только одежды. Отчёты для них одинаковые.
- Запуск: март 2026.
- Масштаб: 27 workflow рекламной статистики (по одному на бренд), 19 из них активны на 12.11.2026.
- Системы: n8n, Facebook Graph API, Google Таблицы, Sitniks, KeyCRM, webhook из CRM магазина.

## Задача

Агентству нужно видеть не только сколько потрачено на объявления, но и что из этого реально покупают. До автоматизации обе части делали руками: таргетолог заходил в кабинет, смотрел, сколько потрачено на каждое объявление, считал и заносил в таблицу. Магазины заходили в таблицу и вписывали количество проданных единиц по дням.

Решение о бюджете зависит именно от продаж: по количеству проданных единиц агентство решает, какие объявления масштабировать, а какие отключить. Чем быстрее появляется информация о продажах, тем лучше решение.

## Что сделали

**Реклама.** Один шаблон workflow на бренд. Каждое утро, в среднем в 06:00 (для разных брендов настроено немного по-разному), он читает таблицу, запрашивает у Facebook Graph API данные за вчера, разбирает ответ в коде и дописывает в таблицу клиента новую строку: потраченный за день бюджет по каждому объявлению. Это шесть узлов. Для нового бренда шаблон копируется.

**Продажи.** В таблицу попадает только количество проданных единиц. Есть два способа:

1. Через webhook из CRM. Как только статус заказа в CRM меняется, workflow сначала проверяет, обработан ли заказ уже, и запоминает его номер, чтобы не посчитать дважды. Затем забирает заказ с товарами, для каждого товара подтягивает дополнительные поля, находит строку в таблице и обновляет количество: практически в реальном времени. Запуск workflow может соответствовать одной продаже. Отдельный ежедневный запуск в 03:00 убирает из памяти заказы старше 30 дней. Всего 12 узлов.
2. Для магазинов на Sitniks: каждый вечер в 22:50 workflow забирает заказы из CRM через API, сопоставляет их с товарами таблицы, считает, нужны ли новые строки, обновляет имеющиеся и дописывает недостающие (девять узлов). Ту же цепочку запускает форма ручной загрузки: так можно догрузить продажи за любую дату.

Для части клиентов продажи теперь вносятся автоматически, раньше их вписывали сами магазины.

**Сводка.** Это лист Google Таблицы за неделю: одна строка на товар, в столбцах даты недели. Наша часть делает две вещи. Автоматизация продаж заполняет проданные единицы по дням. А формула связывает рекламу с товаром по артикулу: она берёт артикул товара, ищет в общем отчёте по рекламной статистике все объявления с этим артикулом за даты недели и суммирует потраченный на них бюджет. Так по каждому товару рядом видно, сколько на него потрачено на рекламу за неделю и сколько единиц продано.

Система не меняет рекламные бюджеты: она собирает и сводит данные, а решение принимает человек.

Экономия времени — это оценка, а не измерение: мы считаем только время, не деньги. История запусков в n8n хранится около двух недель, поэтому цифры запусков показывают этот период, а не всё время работы. Для webhook мы видим не менее 2000 запусков: это предел выборки. Количество заказов у магазинов в месяц мы не публикуем: разброс между клиентами очень большой.

## Что было сложным

Сложности касаются входных данных: иногда маркетолог неправильно указывает артикул или клиент забывает его добавить. Поскольку объявления и продажи сопоставляются по артикулу, такой артикул не даёт их связать: строка не попадает к нужному товару, а исправить это на стороне автоматизации нельзя. Других сложностей, в том числе с лимитами API Facebook, не было.

## Что сделали бы иначе

Девять проектов из десяти, которые подключаются к этому отчёту, стандартные. Для них логичнее с самого начала держать общую логику в одном подпроцессе, а в каждом workflow оставлять только параметры: сейчас шаблон скопирован в 27 workflow, и любое изменение приходится вносить во все копии. Но один проект из десяти индивидуальный, и для него нужны отдельные правки, так что такой подпроцесс должен оставлять место для исключений.

Ограничение: рекламная статистика собирается за вчерашний день, а не в реальном времени; продажи с webhook обновляются сразу, а с вечернего прохода раз в сутки.

## Схема workflow

Реклама: расписание 06:00 → чтение таблицы → Facebook Graph API → разбор ответа → новая строка в таблице клиента. Продажи: webhook CRM → пропуск уже обработанных → заказ и товары → дополнительные поля товаров → строка товара → обновление количества. Вечер: расписание 22:50 или форма → заказы из CRM → сопоставление с товарами таблицы → добавление недостающих строк и обновление.

## Стоимость и для кого

Проект стоил $350. Сейчас агентство на ежемесячном обслуживании, и правки по его запросам входят в обслуживание. По [публичному прайсу](/ru/tsiny/) автоматическая отчётность стоит ориентировочно $440–760, синхронизация остатков $320–600. Это ориентиры, а не оферта.

Подход подходит агентствам, которые ведут много рекламных кабинетов, и магазинам, которым нужно видеть продажи по товарам рядом с рекламой.

## FAQ

### Меняет ли система рекламные бюджеты?

Нет. Она собирает расходы и продажи и сводит их в таблице. Решение о бюджете принимает человек.

### Сколько стоит похожее решение?

Публичные ориентиры: автоматическая отчётность $440–760, синхронизация остатков $320–600. Итоговая цена зависит от количества систем, качества данных и лимитов API.

### Подойдёт ли это, если у магазина другая CRM?

В этом проекте продажи приходят из CRM магазинов: Sitniks и KeyCRM. Если у CRM есть API или вебхуки, её можно подключить.

### Что, если артикул указан неправильно?

Продажа не попадёт в нужную строку. Это ошибка входных данных, которую автоматизация не исправляет.

### Сколько кабинетов можно подключить?

В этом проекте 27 workflow, 19 активных, и сложностей с лимитами API Facebook не было.
